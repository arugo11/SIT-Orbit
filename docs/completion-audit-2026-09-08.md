# 2026年9月8日の実装監査

この監査は、製品要件と main の実装を照合し、API、Web、Mobile、Chrome拡張機能を対象に行った。
通常の検証では合成データとローカルのテスト用モデルだけを使い、大学の実データや外部モデルを呼び出していない。

## 対象と判断

| 対象 | 見つかった不足 | 対応 |
| --- | --- | --- |
| WebとMobile | 行動開始ボタンが静的表示で、承認から完了まで進めない | 既存のAction APIに接続し、根拠表示、所要時間変更、承認、却下、完了応答の表示を実装 |
| Action API | 未発行の行動IDでも完了イベントを作れる | 発行済み提案と元イベントを照合し、同一の完了再送には同じ記録を返す |
| 合成データ画面の再開始 | 固定イベントIDにより、2回目の行動が前回の完了と衝突する | 新規提案はAPIでイベントIDを発行し、完了の再送だけ同じ行動IDを使う |
| Action APIの入力 | 未定義フィールド、重複根拠、legacy経路の個人データ境界が不統一 | 既存のデータ検証とAPI契約に統一 |
| API認証 | productionでも認証設定の欠落で無認証になる | productionの保護対象APIは認証設定がない場合に利用不可とする |
| 再開状態 | 空のストアを注入すると既定ストアに置換される | 明示したストアをそのまま使用 |
| バックグラウンドChat | クライアントがポーリングしないと期限を超えて処理が残る | 600秒の期限を処理自身に適用し、終了時に待機中のストリームを解放 |
| Native Tool Search | 承認済みの実装がmainに未統合 | 今回の作業ブランチへ統合し、未発見Tool、許可範囲、参照元、再開時の重複を追加検証 |
| My Library | scopeを欠いた部分引数の扱いがAPIと拡張機能で異なる | 空引数の既存互換だけを維持し、scopeのない部分指定を拒否 |
| 会話の破棄 | 非選択会話の削除やService Worker再起動後に仮名化情報が残る | 対象会話の対応表と一時参照を消去し、失効した鍵から復元しない |
| SITRUS | 送信が許可された成績項目もフィルターで削除される | SITRUS専用の許可項目を保持し、GPAなどの禁止項目は除外 |
| 初回設定と同意 | 保存できなくても成功表示へ進む | 保存成功を確認してから画面を更新 |
| ワークスペース | 別ウィンドウの全画面利用をSide Panelが検知できない | 保存済みセッションと実在するタブを照合 |
| Chatの中断 | AbortSignalを渡してもAPI再開やTool実行が続く | API通信と各処理境界で中断を確認 |
| ローカルキャリア部品 | 任意スナップショット保存、二重実行、索引更新の競合 | 保存形式を限定し、実行状態と更新順序を検証 |
| CI | Azureスクリプトの構文検査が先頭ファイルにしか適用されない | 対象ファイルを1つずつ検査 |

## 合成データ画面の利用

WebとMobileはB1大宮の合成イベントを使う体験画面であり、学内サービスの実連携画面ではない。
APIがfixtureを明示している場合だけ提案を取得する。
利用者が承認して完了を選ぶと、APIが返した完了日時と行動を表示する。
却下は画面内の状態に記録し、外部サービスへの書き込みは行わない。

提案と完了応答はAPIプロセス内に最大256件、24時間保持する。
これは当日の行動の照合と通信再送のための状態であり、長期的な学生記録ではない。
プロセスの再起動、保存期限、容量超過で失われた提案は、新たに取得する必要がある。
既存のDeferred runと同様に、同じAPIプロセスで処理する構成を前提とする。

## この監査で実施しないもの

- SITRUS、SCombZ、CASTなどの実学生データを使った受入。
- 実AzureモデルのTool Search評価、候補revisionへのトラフィック切替、本番配置。
- 図書館の予約、延長、購入依頼、ILL、CASTへの応募、予約、添付、送信。
- SIT Portfolioの正式統合と、製品スコープ外の恒久的な学生履歴基盤。
- ES支援、キャリア地図、Decision Roomなど、production bundleから明示的に除外されている将来機能のUI接続。

大学サービスへの書き込みには、正式な権限と実際のフォーム、送信後の確認が必要である。
既存の未提供表示を維持し、合成の成功を実連携の成功として扱わない。
Native Tool Searchの既存作業では候補revisionのHealthyまで記録されているが、この監査では実環境を再確認していない。
